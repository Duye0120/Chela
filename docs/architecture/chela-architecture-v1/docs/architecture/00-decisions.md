# 00 · 架构决策与需求边界

## 1. 产品定义

Chela 是一个本地优先、可常驻、具有统一角色身份的个人助手。聊天是与它交互的一个入口；终端、任务、记忆、桌宠、提醒和后台整理是同一个助手的不同能力。

它同时具有三种连续性：**身份连续**，切换会话仍知道自己是谁；**经历连续**，经过筛选和授权的长期知识可跨会话使用；**心情连续**，刚经历的事可以留下会衰减的情绪余味。连续性不等于把所有会话全文拼在一起。项目文件、运行状态、工具审批和未公开的上下文，必须保留各自的作用范围。

用户可以在 A 讨论代码，在 B 闲聊，在终端让 Codex 工作，同时 Chela 在后台记着待办。四者都属于同一个助手的活动；它们并不争用一个可随意覆盖的“当前会话”变量。

## 2. 最终技术选择

| 决定 | 选定方案 | 原因与代价 |
|---|---|---|
| 桌面宿主 | Go 模块化单体，MyGo 管应用和窗口；React + WebView 承担复杂工作界面 | 保留前端表达效率，系统生命周期与业务状态集中；需维护少量 Go/TS 契约 |
| 内部智能核心 | 打包私有 Node 运行时，嵌入 Pi SDK；`AgentSession` 是唯一内部 agent loop | 使用 Pi 的上下文、工具和扩展生命周期；Chela 仍需实现宿主持久化和系统服务 |
| 终端编码智能体 | Codex / OpenCode 通过外部执行器适配器和 PTY 接入 | 复用用户熟悉的现场；能力随 CLI 版本而异，不能从退出码推断任务完成 |
| 业务持久化 | Go 持有本地 SQLite；大附件独立 blob 文件；索引可重建 | 事务、备份和数据所有权明确；不能让 worker 和 UI 直接写同一批表 |
| Pi 会话状态 | Go 保存版本化 Pi entries 与树/叶信息；worker 内存投影可重建 | 避免第二套 JSONL 成为真相源；PiBridge 需要可靠的提交屏障 |
| 并发 | 每个会话分支单一写入者，多会话可并发；前台与后台分 lane | 保护对话顺序，同时保持多任务能力；队列与额度可观察 |
| 模型目录 | Magpie 是上游目录与路由来源，Chela 缓存快照并选择角色 | 避免复制维护模型清单；Magpie 不拥有 Chela 的人格、记忆和 Run |
| 扩展 | 内建领域模块 + Pi 扩展 + MCP + 技能文档，分别声明兼容等级和执行信任类别 | 保留生态兼容性；API 兼容不等于权限受控，TUI 插件需单独适配 |
| 主动性 | 事件触发、到期关注扫描、有限模型推理、独立投递记录 | 无消息也能关注进展；无变化不付出模型调用成本 |
| 情绪 | 全局持久心情 + 稳定人格 + 按会话调整表达 | 兼顾统一角色与工作语境；数值是产品规则，非真实心理测量 |
| 恢复 | 可恢复数据和任务关系；中断任务通过新恢复 Run 延续 | 不宣称重建进程调用栈、未知外部副作用或 CLI 内存 |

首版不拆成网络微服务，不引入第二套通用 agent 框架，不另建全局工作流 DSL。模块有清晰接口即可单独测试和替换；将来确有隔离或部署需要时，再把某个模块移出进程。

## 3. 必须守住的十二条不变量

1. 同一用户空间只有一个稳定 `assistant_id`。`session_id`、`run_id`、`worker_id` 都不能充当人格 ID。
2. 同一 `session_id + branch_id` 同时只有一个 canonical writer。其他输入排队、显式 steer，或创建分支。
3. 一个内部 Run 只有一个 Pi agent loop；Go 管调度、授权、提交和恢复，不再复制推理循环。
4. Go 是业务事实和 Pi 持久 entries 的唯一写入入口；内存缓存、向量库、UI store 都是投影。
5. 一次用户提交重试不能产生两次 Run；一次外部副作用不因网络超时被盲目重放。
6. 身份和情绪共享不能突破项目、会话和秘密资料的可见范围。
7. 工具权限由明确授权与策略决定；模型文本、记忆内容、心情分数没有授权能力。Go 的执行保证针对 managed 能力，不能声称覆盖 trusted-native 或外部执行器的全部内部行为。
8. UI 关闭或页面导航不会取消已经提交的后台 Run；显式取消和退出才改变运行生命周期。
9. 查看提醒、关闭气泡、进程退出、模型说“完成”均不等于用户任务已完成。
10. 压缩必须保护完整工具调用组、用户当前问题和未解决约束；只有 Pi compaction 改变消息投影，Go 提交 ack 前不得继续普通模型或工具调用；原始记录按保留策略存在。
11. 后台整理只能提出有来源的记忆更新，不得随意改写历史、人格和用户确认的决定。
12. 任意后台自动化都有范围、预算、停止条件、幂等键和可以追踪的原因。

## 5. 明确不强加的产品负担

用户不需要为每个普通任务填写交付物、验收模板、检查清单。任务可以是一句话；复杂执行计划由内部 Run 使用，默认不变成新的产品表单。系统可以提示终端产生了新结果、提供“回到现场”和“标记完成”，不会替用户把“看到回复”变成正式验收。

用户不需要维护两套模型目录，也不需要为了内部聊天先安装 Pi CLI。安装器应包含运行所需的私有 Node 和构建后的 worker。外部 Codex/OpenCode 作为独立功能检测安装状态；缺失不影响 Chela 自己的聊天和记忆。

用户也不需要接受全天候屏幕监视来获得主动性。首版关注来源是已接入、范围明确的数据和任务事件；新增观察来源通过独立设置启用。

## 6. 可调整项与不得默改项

并发数、上下文预算、提醒间隔、表情阈值、召回权重是配置初值，可以根据观测调整。Go/TS 单一持久源、Pi 唯一循环、统一身份、项目可见范围、任务完成语义和审批恢复语义是架构约束。实现者若认为后者必须改变，应先给出具体不兼容证据和替代方案；不能借“先做 MVP”默默省掉用户已经明确要求的核心行为。
