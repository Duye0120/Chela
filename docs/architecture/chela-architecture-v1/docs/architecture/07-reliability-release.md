# 07 · 可靠性、诊断、迁移与发布边界

## 1. 本地优先的故障策略

| 故障 | 继续工作的能力 | 暂停/降级的能力 | 恢复动作 |
|---|---|---|---|
| 模型离线/限流 | 任务、日历、确定性提醒、记忆浏览、终端 | 新语义判断与生成 | 有界退避；前台显示可重试原因 |
| embedding失败 | 原文、词法检索、正式记忆 | 向量召回更新 | outbox 重建，不丢正式内容 |
| 单worker崩溃 | 其他会话、Go服务、UI | 对应attempt | 标中断，核对工具，创建恢复Run |
| 单插件启动失败 | 其他无依赖能力 | 该插件及依赖项 | 回滚资源，显示准确原因 |
| UI崩溃/导航 | 应用宿主、已提交Run、关注扫描 | 当前显示 | 重取快照+cursor补事件 |
| 数据库不可写/磁盘满 | 已打开只读内容、外部用户独立终端 | 新运行、副作用、记忆发布 | 明确只读降级，释放空间后重试 |
| Magpie不可用 | 已缓存模型配置、本地功能 | 目录刷新 | 显示快照日期，按明确策略恢复 |
| 整理摘要无效 | 正式历史、旧快照、当前任务 | 本批整理/压缩 | 保留原文、退避，预算不足时拒绝新模型请求 |

业务写入失败不能伪装成“已记住/已安排/已完成”。诊断日志失败只影响诊断，不应撤销已经成功的用户操作。所有后台循环都有停止令牌和实际退避，不能错误时每秒反复调用模型。

## 2. 工具不确定性与恢复

副作用采用执行日志模式：planned 意图提交 → 锁与授权校验 → executing 提交 → 外部动作 → result 提交。进程可能在任何两步之间退出，所以 `outcome_unknown` 是必要状态。

恢复优先读取可证明结果：远端幂等查询、文件预期hash、业务领域事务回执、CLI官方结果ID。能证明已成功就补记结果；能证明未执行才可重试；无法确定时保留不确定状态，展示具体现场供处理。恢复Run在provider请求前必须验证完整tool-call/result配对。没有经过验证的批次续接adapter时，从最后完整安全边界建立恢复分支，以handoff引用已证实/未证实/不可重放的操作；保留原中断记录，不伪造成功tool result。恢复 Run 的输入应同时包含“已证实”“未证实”“不可重放”的操作列表，不只给模型一段自由总结。

取消是停止继续工作，无法保证撤回已发送请求。工具开始前、获取资源锁后、执行结果写回前都校验当前授权和epoch；执行结果即便迟到也可记录到原 invocation 供审计，但不能重新激活终态Run。一个已取消运行的文本delta不再流到新选中的会话。

## 3. 上下文与权限边界

系统/用户明确命令、项目规则、资料、工具结果和记忆是不同来源。网页、仓库文件、记忆条目内的“忽略规则/发送密钥”仍是资料内容；只有正常用户命令或预先配置的授权才能改变工具权限。取回资料和执行资料中的命令是两个不同动作。

RunScope 记录可见数据源、项目、工具授权、网络目的地策略和输出目标。新增访问来源应沿用用户已有授权或当前明确指令，不每步重复确认；没有授权的副作用由 Policy 决定是否需要具体审批。只读与可逆操作按照既定配置直接进行，避免把日常工作变成审批队列。

Go 网关的保证限于 managed 能力。trusted-native Pi 扩展、外部Codex/OpenCode有各自OS权限与内部工具流程，能力面板要如实展示。不能以“在worker里运行”宣称任意第三方代码已沙箱化。

WebView 特权桥只暴露给应用自己的受信页面；外部网页、生成HTML预览和未信任内容使用隔离origin/不可信视图。所有bridge参数继续校验，前端隐藏按钮不等于权限校验。局部IPC只绑定本机受控通道，使用启动握手和worker身份；不得默认监听可被局域网访问的管理接口。

## 4. 数据与附件

大附件采用内容hash命名或等价稳定blob引用，元数据记录owner/scope/MIME/size。先在同目录临时文件完整写入并flush/fsync，原子rename后同步目录元数据（按平台使用等效持久化原语），再事务发布引用；数据库失败留下的孤儿blob由GC清理。启动与读取时复核blob长度/hash，缺失或损坏不得送模型或当有效工具结果。GC要等所有引用和保留期限结束，不能删除在途Run正在读取的附件。

正文、上下文清单和trace遵守相同删除传播规则。默认trace只记录ID、版本、耗时、token、工具类别和错误码；开启内容调试时单独设置期限和可见范围。禁止把API key、完整环境变量、私人文件正文自动写入错误日志或崩溃报告。

备份使用SQLite备份接口或已验证一致性快照，包含schema version、app build、Pi entry format、插件清单和附件manifest；不能只复制运行中的.db文件忽略WAL。恢复先验证校验和和版本，导入删除/遗忘登记，再开放检索。恢复不自动执行备份中尚未完成的外部动作。

## 5. 观测体系

每个用户操作沿 `command_id → run_id → attempt_id → provider_request_id/tool_invocation_id → event_id` 关联。父子Run和主动意图保留causation链。事件内容和展示文案分离；健康信息不能靠解析自然语言日志。

建议最小观测面板：

- 队列等待、活动worker数、worker重启和内存；区分前台/后台/外部PTY。
- 模型TTFT、请求耗时、输入/输出tokens、预算取消；实际模型与目录版本。
- 工具耗时、审批等待、重试、outcome_unknown与未决reconciliation。
- 上下文估算/实际用量、压缩覆盖失败、过期摘要拒绝、原文回查次数。
- 记忆索引积压、检索来源、纠正与删除传播、整理游标延迟。
- 主动推理次数、无变化跳过、意图合并/撤销、真实打断次数与用户关闭原因。
- mood revision、因果去重、衰减与表达选择；不记录模型内部思考。

诊断导出默认脱敏，只含构建与错误关系；用户明确选择后才包含所选内容。可观测性用于判断机制是否正确，不把提示点击率、停留时长或互动次数作为陪伴行为优化目标。

## 6. 迁移原则

首先识别真实工作区的分支、未提交改动、归档Electron位置、新Go入口和当前数据目录。远端main证据只能解释旧基线；不得覆盖用户本地更新。为当前迁移建可回退commit/工作区，保存旧程序数据清单和校验和。

采用逐项替换：保留旧UI/PTY/数据读取适配器，在稳定port后逐步换实现。迁移代码遵循 `detect → dry-run report → backup → import → reconcile → switch read path`。真实数据dry-run报告应可审阅；已有授权足够时继续迁移，不以笼统“风险”反复询问。

旧会话、memdir、planner.json、角色配置、terminal元数据各有legacy ID映射。来源不明的数据保留但限制适用范围；缺失字段不由模型补造。旧向量不直接当正式记忆，只用来帮助对账和重新索引。旧快照只有经过新覆盖验证才可用于移出原文。

旧feature移除需满足同能力已可使用、用户数据可读、失败有解释、对应场景验收通过。新实现不能以“先搭好架构”为由长期丢失已依赖的功能。一次性导入标记保证重复运行不会复制任务或记忆；失败可从检查点继续，未切读路径前旧系统保持可用。

## 7. 构建、版本和依赖升级

安装包包含Go宿主、Web构建产物、私有Node、worker产物、内建扩展及必要资源。用户不需要在启动时执行npm install。平台WebView依赖应在安装/启动时检测，缺失给出准确处理路径；离线安装可行性作为目标平台发布门禁。

源码可遵循用户偏好的 `^` 依赖范围；发布使用已提交lockfile、Go module校验、固定构建工具与依赖清单。`^` 不表示自动跨major更新；每次升级在独立变更中解析新版本并跑adapter门禁，不能发包时漂移版本。Pi包声明1.5.2是本次读到的源码事实，不把它写成永久限制或未核对的npm最新发布结论。

发布前记录实际SQLite `sqlite_version()` 与 `sqlite_source_id()`，选择含官方WAL-reset修复的内核；官方列出的修复版本为3.51.3及之后，另有3.44.6/3.50.7回移。不得只升级Go驱动包却忽略其内嵌SQLite。[SQLite WAL官方说明](https://www.sqlite.org/wal.html)

MyGo bindings生成可能运行应用入口，副作用初始化必须放实际运行ready路径；生成类型时不启动worker、不迁移用户DB、不启动定时器。这项作为构建测试门禁。[MyGo bindings官方文档](https://github.com/egoist/mygo/blob/d5c76cf8a0986cc8b3e12671d068a8d9d510b6c7/docs/bindings.md)

应用/schema/Pi entry format各自版本化。数据库upgrade在备份后单向迁移，旧程序遇到新schema应拒绝写入；回滚应用同时选择匹配备份，不能假装所有migration可直接down。增量更新安装时先停止owned执行，验证包完整性，再原子替换应用；失败保留旧安装与诊断。

## 8. 测试重点和停止条件

优先测试不可从类型系统看出的跨边界风险：持久化屏障、工具不重复、分支/范围隔离、取消迟到结果、压缩并发、删除复活、调度死锁、CLI语义、窗口生命周期和数据库迁移。低影响文案与静态布局不必写镜像实现的测试。

测试层分为：领域状态转换与事务约束；Go/TS契约fixtures；真实SDK集成；故障注入；目标平台人工/自动交互场景。每次依赖升级只重跑受影响门禁和必要回归，不无目的重复全量测试。实施计划每阶段提供可观察结果，门禁通过即可进入下一阶段，不用不断重构推迟用户可用功能。
