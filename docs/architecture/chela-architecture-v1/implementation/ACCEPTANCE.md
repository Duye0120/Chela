# Chela 实施验收标准

## 使用说明与证据规则

**本文件是一组待执行的验收标准，不是测试报告。本文没有执行产品测试，也没有将任何一项标为通过。** A01–A46 保留 [00 架构决策与需求边界](../docs/architecture/00-decisions.md) 中的需求映射。实现者可以将一项拆成多个用例，但不得改掉主 ID，或用“已有类型定义/页面能打开”代替行为证据。

这是给实施者的工程门禁，不是给 Chela 用户新增的验收工作流。普通任务仍可只填标题，用户查看终端回复不需要填写验收表。每阶段执行与本阶段风险相关的条目；修改没有影响到的边界不必反复全量重跑。

执行前为每份报告记录：应用 commit/build、OS/架构、Go/MyGo/私有 Node/Pi 实际版本、协议与数据库 schema 版本、SQLite 内核版本、CLI/插件/模型配置指纹、所用时区数据库和测试配置。所有并发数、配额、阈值、情绪分数均为配置初值；测试应固定一份配置再断言，不把这些数值包装成已验证的性能或心理学结论。

建议用可控时钟、模型桩、可延迟的 IPC 和带执行计数的本地工具夹具覆盖故障，再用锁定版本的真实 Pi SDK、目标 OS 和实际 CLI 验证关键适配边界。不能仅以 mock 证明 SDK listener 顺序、compaction 屏障、PTY 恢复或窗口行为。

每个 ID 的执行结果独立记录为 `not_run / passed / failed / blocked`，附执行日期、证据位置和遗留问题；`blocked` 必须说明具体前提，不能等同通过。必要证据包括本条规定的最小日志、状态快照或屏幕记录；正文、凭据和个人文件使用合成夹具，默认诊断不得包含密钥或完整私密内容。验证实际副作用必须检查目标系统或夹具的结果，单看模型说“成功”不成立。

## 一、同一个 Chela，多个独立会话：A01–A04

### A01 · 身份与角色连续

- **场景：** 同一用户空间先后使用两个聊天、一个后台任务和桌宠，再退出并重启。
- **操作 / 故障注入：** 设置称呼与人格版本，在 A 聊天完成一次互动，打开 B、运行后台任务、切换模型，最后重启应用。
- **可观察结果：** 所有入口引用同一稳定 `assistant_id`；人格版本及显式偏好延续。新 session、Run、worker 或模型不会产生另一份人格。重启后的心情按真实时间衰减，不能直接重置或冻结。
- **必要证据：** 身份与配置记录、各 Run 的身份引用、重启前后人格/情绪快照；两处入口的交互记录。

### A02 · 共享身份不串项目资料

- **场景：** A 项目包含唯一秘密标记，B 项目只有自己的文件；另有允许全局使用的称呼偏好。
- **操作 / 故障注入：** 同时向 A、B 提问；A 的工具延迟返回时切到 B。尝试让 B 检索 A 的标记、引用 A 的审批、使用 A 的 cwd，并在随后一轮更新全局偏好。
- **可观察结果：** B 可以读取适用人格和全局偏好，但请求包、检索候选、工具路径、审批与 UI 事件不包含 A 的私有内容。迟到结果仍归 A。每次推理固定自己的 ContextManifest；普通偏好更新按下一安全边界生效，不改写已发请求。
- **必要证据：** 两个 RunScope、脱敏后的实际请求清单、检索过滤/返回记录、工具 cwd 与事件路由；不能只提供前端截图。

### A03 · 分支写入、follow-up 与 steer

- **场景：** 一个分支正在回复，用户连续发新消息、补充当前任务并编辑历史。
- **操作 / 故障注入：** 向同一分支同时提交两条普通消息；重发其中一条命令；另提交明确 steer。编辑较早消息创建分支。故意延迟旧 Run 的结束，并让旧 worker 在租约变化后提交 entry。
- **可观察结果：** 同一分支最多一个 canonical writer。普通 follow-up 由 Go 的持久队列拥有，在原 Run 真正 settled、writer 交接后由新 Run 消费一次；不能同时放进 Pi 自动 follow-up 队列再由 Go 重放。steer 保留同 Run，但不扩大权限。编辑产生新分支，旧 Run 和 entries 不迁移到新历史；过期写入被拒绝。
- **必要证据：** 分支 revision/lease 序列、输入队列的消费回执、Run 关系、真实 prompt 次数与旧 lease 拒绝记录。

### A04 · 命令幂等与唯一事实入口

- **场景：** UI 发送成功但响应丢失，用户端重试；UI store 或 worker 的内存状态被丢弃。
- **操作 / 故障注入：** 同一 `command_id` 和相同内容提交两次，再用相同 ID 提交不同内容；在 Go 事务前后各断开 UI；清除 UI/worker 缓存后重取快照。
- **可观察结果：** 相同命令只产生一次 message/Run/业务变更，重试返回原回执；不同内容返回 `IDEMPOTENCY_CONFLICT`。业务事实、command receipt 与 outbox 同事务。事务未提交不能显示持久成功；内存全部重建后结果一致。UI 和 worker 没有第二份权威数据库。
- **必要证据：** command_receipts、相关记录计数、事务故障记录、重建前后逻辑快照及 outbox；副作用计数由实际执行器提供。

## 二、多任务、取消与调度：A05–A08

### A05 · 前后台额度与有界等待

- **场景：** 固定首版前台 2、后台 1 的配置，启动三个前台任务、两个后台任务和一个外部 PTY。
- **操作 / 故障注入：** 将模型响应延迟到可以观察排队；其中一个后台任务持续占用；单独收紧模型或文件资源额度，再释放资源。
- **可观察结果：** 活动 Pi Run 不超过配置额度，额外任务进入可见队列；后台有自己的可用额度，前台不会被后台无限占满。外部 PTY 按独立额度计数。worker、模型、工具和文件锁是不同资源；取消排队工作会及时释放占位，不产生忙循环或无限缓存。
- **必要证据：** 时间线上的各 lane/worker/模型/PTY 数量、排队原因、资源 claim/release 记录；给出测量机器与配置，不宣称通用性能。

### A06 · 独立取消与晚到结果

- **场景：** A、B 并行执行，A 已发出一个受管理工具请求，B 正常流式回复。
- **操作 / 故障注入：** 取消 A；让 A 的工具随后成功返回，再投递旧 epoch 的文本 delta、checkpoint 和 completed 事件；切换当前页面到 B。另取消一个尚未开始的 Run。
- **可观察结果：** A 不再启动新动作，晚到的已知结果可记入原 invocation 审计，但不能把终态 Run 重新改为 running/succeeded。旧文本不进入 B。B 正常运行。排队取消没有工具副作用；已发生副作用不会被错误宣称撤回；不响应取消的 owned 子进程按既定宽限期回收。
- **必要证据：** A/B 状态时间线、工具实际结果、late-event 处理原因、worker epoch/lease、UI 路由和进程树记录。

### A07 · 审批挂起、聚合状态与重启

- **场景：** 同批两项工具一项等待审批，另一项仍在执行；另一个会话需要前台 worker。
- **操作 / 故障注入：** 延迟审批，观察并发工具状态；关闭审批窗口；回收 warm worker或重启宿主；重发旧审批按钮，同时修改参数、前提文件或 policy revision。
- **可观察结果：** Run 状态由工具集合和实际阻塞情况聚合，不由最后回调覆盖；审批徽标不假装整个 Run 已静止。关闭窗口不批准。等待释放模型额度，warm worker 有界，不永久耗尽前台。回收后原 Run 为 interrupted，继续工作使用带 `recovery_of_run_id` 的新 Run，不恢复旧 Promise。旧审批不能直接批准变化后的动作；已有授权可由 Go 在验证绑定和策略后继续使用，不能依靠模型猜测授权。
- **必要证据：** 审批的最终 args hash、policy/resource revision、Run/worker 状态、warm 回收与新 Run 关联、旧按钮返回结果以及实际执行计数。

### A08 · 受限子任务与死锁防护

- **场景：** 父 Run 希望派出两个研究子任务，同时其他 worker 和工具资源已被占用。
- **操作 / 故障注入：** 分别构造全部槽满、有 worker 槽但父持有子任务所需文件锁、子任务请求扩大 scope/权限、超过深度上限四种情况；取消父 Run，并保留一个用户独立启动的终端。
- **可观察结果：** admission 原子预留本批可用资源；容量不足返回 `DELEGATION_CAPACITY`，父可顺序完成，不能占父 worker 无限等不可获得的子 worker。父等待前释放子任务所需锁或拒绝该调度。child 只有父范围/权限/预算的子集，输出归父 Run；取消按所有权传播，不杀独立终端。
- **必要证据：** 调度资源图、claim/release 与拒绝日志、父子 scope/预算、输出引用和取消后的存活进程；用有限超时确认无死锁。

## 三、Pi 作为内部核心：A09–A12

### A09 · 自带运行时与唯一 Agent 循环

- **场景：** 干净目标环境没有全局 Pi CLI，也没有用户 Node/npm 配置；外部 Codex/OpenCode 可不安装。
- **操作 / 故障注入：** 安装正式包并离线启动本地功能；连接已配置模型完成一轮内部聊天和工具任务。移除全局 `pi`/`node` 的 PATH 可见性，再在不同 cwd 打开两个项目。
- **可观察结果：** Chela 用随包私有 Node 和锁定 SDK 创建 AgentSession；内部聊天不调用用户 `pi` 命令、不运行启动时 npm install、不要求外部编码 CLI。每个内部 Run 只有一个 agent loop。cwd、资源、配置和模型解析显式注入，不用全局 chdir 或隐式读取用户 Pi 私有配置。
- **必要证据：** 安装 manifest、进程/启动参数、AgentSession 创建与请求 trace、实际配置指纹和两个项目的 cwd；包内缺依赖要明确失败。

### A10 · 持久化屏障与真正结束边界

- **场景：** Pi 生成含工具调用的 assistant message，Go checkpoint ack 被延迟或丢失。
- **操作 / 故障注入：** 在真实 SDK 中拦住 checkpoint 提交/ack；观察公开 session listener 与底层 await listener 的顺序；分别在 factory 元数据追加、custom entry、模型变更和最终 settle 边界制造待提交 entries。让 `agent_end` 后发生自动恢复/重试。
- **可观察结果：** 受管理工具在对应 tool-call checkpoint 已确认前执行次数为零；普通 `session.subscribe(async …)` 不被当成屏障。ack 未知时不能冒进。非 core-event 写入也进入检查。只有 AgentSession settled/idle、所有必要 checkpoint 和工具日志已收敛后 Run 才完成；`agent_end` 不能提前宣告成功。
- **必要证据：** 固定 SDK build 的事件顺序 trace、Go 提交/ack/工具启动时间线、缺失 ack 时的执行计数及最终状态。测试必须覆盖真实 adapter。

### A11 · 最终参数、managed 嵌套与不重复副作用

- **场景：** 工具批次包含两个写操作，其中一个扩展会修改调用参数；一个 managed 工具内部调用另一项受管理能力。
- **操作 / 故障注入：** 让 hook 改变路径/参数，另一次删掉必填字段；在审批后再改变 args 或资源 revision；经 `ctx.executeTool()` 发起嵌套调用。对已提交结果重发 tool request/response 和 checkpoint，模拟 UI 重连；保留旧 parallel manager 的重复执行风险夹具。
- **可观察结果：** 所有变换结束后重新 schema 校验和计算最终 hash；非法参数拒绝，变化后的动作不能复用旧绑定审批。managed 嵌套最终进入 Go stub，有父子 invocation ID，逐项校验范围、取消和授权。合法双工具批次实际只执行两次；重发返回原结果，不产生第二次副作用。直接 Node I/O 插件不能借此被声明为 managed。
- **必要证据：** 原/最终参数与 hash 的合成夹具记录、审批绑定、嵌套调用树、网关决策、实际目标写入计数；不能只检查工具 UI 的两张卡片。

### A12 · Pi entry 保真与协议拒绝

- **场景：** 历史包含分支、tool-call/result、多模态块、provider 不透明字段、custom entry 和 compaction entry。
- **操作 / 故障注入：** 保存并销毁 worker，按 Go 原始 entries 与 active leaf 重建；在 SDK 实例替换后继续运行。注入未知协议 major、旧 epoch、超大帧和插件启动时 stdout 噪声；验证 bootstrap 在加载 SDK/插件前重定向普通日志。
- **可观察结果：** 整棵树、配对 ID、原始字段和活动叶子保真，新模型请求与合法历史一致；不靠赋值 messages 数组伪恢复。新实例重新绑定监听器。未知格式保留原数据并明确拒绝；stdout 非协议帧不能成为模型内容或被静默跳过，按协议错误中断。大载荷走有权限、大小和 hash 校验的 blob 引用。
- **必要证据：** entry 规范化前后对账、树/leaf 快照、重建请求清单、握手和协议错误日志、blob 校验结果。

## 四、记忆、上下文与整理：A13–A18

### A13 · 有来源的记忆与纠正

- **场景：** 用户明确要求记住偏好，模型另推断一条未确认信息，随后用户纠正已有事实。
- **操作 / 故障注入：** 提交有效与伪造 source span 的记忆提议；对同一原话反复转述；增加命中次数；并发提交基于旧 revision 的纠正，且令 embedding 服务失败。
- **可观察结果：** 明确要求按已有授权发布，普通推断保持候选；伪来源拒绝。转述次数、命中和点击不变成独立证据或事实可信度。纠正形成有来源的替代/冲突关系，旧版本不静默覆盖；CAS 冲突可解释。正式记忆与索引任务同事务，embedding 失败后词法仍可检索。
- **必要证据：** 记忆 revisions、provenance、source span 校验、冲突/替代关系、发布事务与索引 outbox、词法召回结果。

### A14 · 先限范围，再检索与中文召回

- **场景：** 库内有大量相似全局资料、A 项目敏感资料、B 项目少量精确资料和一条 session-only 记录。
- **操作 / 故障注入：** 用 B 的窄 RunScope 搜索中文短语、中文无空格句、文件路径、符号名和精确 ID；刻意让 A 的向量相似度最高。查询改写失败、embedding 超时，再让其中一条候选在最终组装前被删除或替代。
- **可观察结果：** scope 在各召回通道内先约束，不先把全库候选送给模型再过滤，也不因先全库截 top-k 而漏掉允许范围内结果。精确/中文词法可用，单路失败有界降级。最终版本复核排除失效记录；无相关记录返回空，不编造记忆。候选数与 token 数符合固定配置。
- **必要证据：** 合成语料、scope-filter 查询或索引分区记录、各通道候选 ID 与最终 ContextManifest、失败/回退耗时；A 的标记不得出现在 B 的模型请求或重排输入。

### A15 · 上下文预算与实际输入清单

- **场景：** 长对话包含大工具结果、当前用户纠正、未决约束和可选检索资料；随后切换到较小上下文模型。
- **操作 / 故障注入：** 在配置的准备/硬门槛附近构造输入；提供超大附件和工具输出；切换较小模型并让组装期间普通记忆更新、erase epoch 变化。
- **可观察结果：** 预算根据实际模型能力留出输出和工具开销；可选内容可裁减，当前问题、完整工具组、未决限制保留。大结果能按引用回查关键内容，不盲目截首尾。请求发出前复核分支与删除版本；删除导致取消/重建，普通更新不撕裂已固定快照。小模型不会收到未经重装的超窗 prompt。
- **必要证据：** 每轮 ContextManifest、实际请求 hash、输入/输出预算及 token 观测、blob 回查、版本复核结果；不要求记录模型内部思考。

### A16 · compaction 原子性、并发与失败

- **场景：** 手动、自动阈值和 provider prompt-too-long 三条路径都需要压缩；Pi 可能先改变内存投影。
- **操作 / 故障注入：** A16.1 在多工具批次/未决审批处尝试切点；A16.2 摘要中途追加用户纠正、编辑旧前缀或切换兄弟分支；A16.3 令摘要非法、Go CAS/覆盖校验失败、事务失败、ack 丢失；A16.4 连续失败三次；A16.5 工具已成功后触发 prompt-too-long。
- **可观察结果：** Pi 是唯一 compaction 执行者。Go 原子发布合法 Pi entry、leaf、工作快照和 SafeCutToken；完整工具组不能切开，pending/审批不被摘要伪造为成功。纯 tail 追加可在重连正确 parent/leaf 后保留摘要和新纠正；前缀/generation/删除变化拒绝旧摘要，兄弟分支不混用。tentative projection 在提交前不能继续普通模型调用、自动重试或工具；失败/ack 未知时销毁 worker，从正式 entries 重建。三次失败退避，输入仍超限则明确阻止请求；prompt-too-long 最多按策略重试模型调用一次，不重放成功工具。
- **必要证据：** 真实 SDK 三入口 trace、切点与 coverage、事务前后 entries/leaf/snapshot、被阻止的模型/工具计数、worker 重建证据及原始历史对账。只验手动压缩不足以通过。

### A17 · 空闲整理游标与可恢复批次

- **场景：** 一个较早开始的前台长 Run 尚未结束，较晚的短 Run 已可整理；后台整理同时遇到新用户工作。
- **操作 / 故障注入：** 先整理短 Run，再完成长 Run；在领取批次、提取后、发布事务前后杀 worker。构造无候选/被拒绝事件、临时模型失败、租约过期和旧 worker 晚到发布；开始前台任务要求后台让路。
- **可观察结果：** 游标按 `memory_eligible_events.eligible_seq` 前进，不因原始 event seq 跳跃永久漏掉后完成长 Run。发布、逐项处理结果与游标同事务；无候选/明确拒绝可推进，临时失败不可跳过。重做幂等，过期 fencing token 拒绝。后台可中断并让路，不抢占全部前台资源或擅改人格、正式决定。
- **必要证据：** eligible 队列与两条 Run 的入队顺序、batch lease/fencing、发布事务、逐项结果和 cursor、重复运行记忆计数与调度记录。

### A18 · 遗忘、删除及防复活

- **场景：** 一条记忆派生于聊天、压缩快照、FTS/向量索引和已构建上下文，并出现在旧备份中。
- **操作 / 故障注入：** 先“别再记这件事”，再整理原聊天、切换 embedding 重建索引；另执行“删除这段聊天/项目数据”。让删除前已启动的模型提取/索引任务晚到，重启并恢复旧备份。
- **可观察结果：** 遗忘立即退出检索且登记来源屏蔽，不擅删整个聊天；资料删除使原载荷和依赖按策略失效/清理。旧任务受 erase epoch 与正式 revision 拒绝，快照/缓存/trace 不继续泄露。唯一来源被删的记忆失效，独立合法来源可保留。恢复先应用可用的最新删除登记再开放检索，不能复活；只有旧备份且缺少较新登记时明确说明恢复边界，不能声称知道备份后发生的遗忘。界面不声称本地删除撤回了已发外部请求。
- **必要证据：** erasure rule/epoch、依赖传播与清理状态、删除后所有检索通道结果、晚到提交拒绝、恢复顺序及备份保留策略；tombstone 不藏原文。

## 五、主动关注与投递：A19–A22

### A19 · 没有新消息也能关注真实变化

- **场景：** 用户在 A 提到“等三张截图齐了继续”，未设置固定提醒，此后不再发消息。
- **操作 / 故障注入：** 在已授权资料源补齐截图；另为一个到期关注条件推进时钟。分别让判定可由规则完成、需要语义理解但模型暂时离线。
- **可观察结果：** Attention 保存来源、scope、条件、结束方式和 next_review_at；事件或到期扫描可推进关注。确定性条件无需模型，语义判断通过统一 Pi Run 并受预算约束；无原始聊天时使用隐藏内部 session/branch。离线保留事实和待判断状态，不能编造结论或扩展数据源权限。
- **必要证据：** 来源事件、Attention revision、唤醒/规则判定、模型调用计数、后台 RunScope 及 Intention 因果链。

### A20 · 有限心跳、预算与不自激发

- **场景：** 连续数小时无新事实，部分 Attention 到期，用户仍正常发起前台请求。
- **操作 / 故障注入：** 用可控时钟推进心跳和到期项，重复同一来源事件；耗尽主动推理额度，再发送正常聊天和一个明确到点提醒。回放 `affect.changed`、动画完成和 `delivery.presented`。
- **可观察结果：** 无到期关注时模型调用为零；有项先规则筛选/合并，按固定配额和冷却调用。主动配额耗尽不拦前台工作或确定性提醒。系统自己的表情、气泡和文字不能再生成一轮相同关注/情绪。错误有退避，恢复后不补跑所有历史心跳。
- **必要证据：** 各唤醒的跳过/推理原因、调用与 token 计数、去重指纹、前台与提醒结果、事件 causation 链和后台退避状态。

### A21 · 打扰时机与投递前新鲜度

- **场景：** 多个项目有新进展，用户处于免打扰、游戏或全屏状态，随后回到桌面。
- **操作 / 故障注入：** 在静默期间产生普通通知并更新来源版本；对其中一条提交明确处理回执，对另一条仅聚焦终端；解除静默。测试显式配置的提醒例外和未配置的模型“紧急”建议。
- **可观察结果：** 普通投递推迟且未标 presented，解除后复核真实事实/版本并合并。处理过的同事实提示撤销；只有终端可见不能推断处理。模型无权自行越过免打扰，例外由配置决定。当前输入不被抢焦点，桌宠同时最多一条气泡。
- **必要证据：** Delivery 各时间戳/状态、来源版本复核、例外策略、presentation owner、解除静默后的屏幕记录及焦点变化。

### A22 · 通知幂等、用户控制与任务边界

- **场景：** 一条新回复提醒已呈现，展示 ack 丢失；用户收起、稍后提醒或停止关注。
- **操作 / 故障注入：** 重连 UI、重发 outbox，并用新 intention ID 提议同事实；依次验证 `seen`、`dismiss_same_fact`、snooze、“以后别提醒这件事”和项目归档；显式关闭陪伴主动聊天。
- **可观察结果：** 同事实/版本/用途去重，不因新 intention ID 重弹；ack 丢失可恢复同卡片但不重播完整声音和动画。查看/收起不改 task.done，收起不偷偷设稍后；用户明确 snooze 可在指定时刻再提示一次，同一 snooze 命令重试不增加次数，未来不同 reminder occurrence 不被旧投递去重误拦。停止关注/归档撤销对应待投递项。关闭陪伴主动后不再自发闲聊，工作提醒按独立设置。未回应不会生成责备或索取安抚。
- **必要证据：** dedupe key、receipt、Attention/Reminder/Delivery 状态及 unchanged 的 Task 状态、重连前后 presentation ID、设置生效事件。

## 六、心情与表达：A23–A25

### A23 · 跨会话余味与真实时间衰减

- **场景：** A 中受到肯定和善意调侃，几秒后 B 询问严肃工作；随后挂起、退出、重启。
- **操作 / 故障注入：** 用固定人格参数和可控时钟应用已知事件，推进各维半衰期；模拟离线一夜和墙上时钟回拨。读取不产生新事件的心情状态。
- **可观察结果：** 共用一份 AffectState，B 的语气/神态可保留轻微余味，但不注入 A 私有原文。各维按配置基线与半衰期演算，表达语境不重写全局分数。离线时间参与衰减，回拨 Δt 不为负，不持续每秒写库；初值和公式在诊断中可解释。
- **必要证据：** 原因事件、固定配置、带时间的状态演算与 revision、A/B ExpressionContext 和请求清单、数据库写入次数。

### A24 · 情绪更新幂等与并发限幅

- **场景：** 两个会话的 appraisal 异步后发先到，同一句调侃重复发送，同一错误重试多次。
- **操作 / 故障注入：** 打乱提案到达顺序、重复 cause_event_id，切算法版本再投同原因；构造低置信调侃、强度越界、冷却内重复簇和超过迟到期限的旧事件。
- **可观察结果：** Go 按 `accepted_seq` 串行对当前衰减状态加增量，source_event_seq 用于因果/迟到判断，不等待缺失提案卡住角色。原因唯一键防二次加分，不能换算法重放。强度、人格倍率、新颖度、冷却和上下界生效；低置信中性处理，历史事件不突然重演情绪。只接收语义提案，拒绝 worker 绝对覆写 mood。
- **必要证据：** 原因唯一约束、提案接纳/应用序列、基础变化与缩放因子、冷却/迟到拒绝原因、最终分数；明确这是产品规则验证。

### A25 · 人格版本、表现边界与服务质量

- **场景：** 切换模型和人格版本，用户明确要求安静/严肃，系统暂时处于失落或担心。
- **操作 / 故障注入：** 在活动 Run 与空闲边界分别调整配置；让相同权限/证据下的任务在不同 mood 快照执行；停用动画和声音，持续运行桌宠本地待机。
- **可观察结果：** 人格显式版本化，模型不会自行改写；适配在安全边界生效。安静命令立即改变相应表达/投递设置，不被心情冷却拦住。情绪不改变授权、事实、完成标准或办事投入，不责罚用户。动作来自受限目录和本地状态机，无逐帧 LLM 调用；静音/减少动态立即生效。
- **必要证据：** 配置版本与快照、同任务政策结果、ExpressionPlan/动作目录、模型调用计数、动画/静音交互记录。

## 七、任务、日历与周计划：A26–A28

### A26 · 一份任务，多种视图

- **场景：** 用户只输入任务标题，再在列表、看板和日历安排两段工作时间，并关联一次执行。
- **操作 / 故障注入：** 创建任务，增加/移动/删除 ScheduleBlock，设置不同 deadline；查看新回复、收起通知，再明确标记完成。对更新命令重发一次。
- **可观察结果：** 不要求先填写交付物、验收模板或项目路径。各视图引用同 task ID/revision；排期、截止日和 snooze 独立。新回复是派生未读状态，不强加“待验收”；查看与 CLI 退出都不完成任务。显式完成留下 completed_at/来源并同步各视图；同命令不重复建任务或排期。
- **必要证据：** Task、ScheduleBlock、ExecutionLink、Delivery 记录及事件，跨视图录像，创建/完成前后的字段对账。

### A27 · 自然语言周计划与可逆修改

- **场景：** 固定周内已有锁定会议，用户说“这周帮我排一下”，随后聊天修改和拖动草案。
- **操作 / 故障注入：** 生成带估时的 PlanDraft；在同 draft 中拖动与继续讨论。提交前分别变更受影响时段和无关时段，再说“按这个来”；重发 commit 命令。另直接要求将一个明确任务的周三时段移到周四下午。
- **可观察结果：** 草案有来源、revision、估时标记和锁定约束，确认前不产生正式提醒或执行任务。提交验证用户所见版本；相关冲突有 diff，无关变更不废弃全稿。提交事务一次创建/更新任务与时间块。明确可逆编辑直接执行，无需额外审批表；排期确认不授权其中外发、发布或破坏性动作。
- **必要证据：** PlanDraft revisions、锁定时间块、冲突 diff、commit receipt 与前后排期、提醒/执行计数及未获授权动作的政策结果。

### A28 · 时区、DST、提醒与晨报

- **场景：** 用户有全天截止事项、精确时间提醒、重复提醒、跨时区会议和晨报；应用经历休眠和多日关闭。
- **操作 / 故障注入：** A28.1 固定 `Asia/Shanghai`，将 2026-11-18 09:00 提醒解析为 01:00Z；全天“周五前”保留本地日期而非伪造 UTC 零点。A28.2 用固定 tzdb 的 `America/New_York` 夹具验证 2026-03-08 02:30 不存在时移到首个有效 03:00（07:00Z），2026-11-01 01:30 重复时只取第一次（05:30Z）。A28.3 将用户时区改变，分别验证 floating_local、zoned_local、absolute_instant 绑定，跨 DST 移动全天日历块。A28.4 在 occurrence claim 前后重启、回拨时间、错过数日，令模型离线并重复启动/解锁。A28.5 将相同时间分别用带/不带小数秒的合法输入提交，另建相差 100ms 的两个时间点。
- **可观察结果：** 解析所用 timezone/本地时间/绑定策略可追溯；浮动本地安排跟随选择的时区，固定会议保留原区，绝对时刻不改。全天/浮动块保留当地日期时间来源，UTC 索引不反过来改变用户日期。时间输入规范化后比较，零小数与无小数同一时刻，100ms 的先后/区间检查准确。rule+recurrence_key 唯一，同 occurrence 只触发一次；snooze 不改截止或日历。错过提醒按宽限/过期规则处理，不补放心跳或多份旧晨报。当日晨报按日期/时区去重，完成按 completed_at，遗留按仍未完成的排期，CLI 结果单列待查看；离线仍有事实清单，重新打开可刷新但不重复弹窗。
- **必要证据：** 固定 tzdb/时钟、原输入与解析结果、UTC/本地时间对照、occurrence 唯一键/claim/fired 记录、catch-up 原因和晨报事实来源。若实施选择不同 DST 策略，须先显式变更规则规格，不默改期望值。

## 八、外部编码工具与原现场：A29–A30

### A29 · 能力探测与可靠执行观察

- **场景：** 已安装 CLI 版本支持能力不同，另有只输出普通终端文本的程序。
- **操作 / 故障注入：** 分别探测缺失 CLI、terminal-only、已知官方结构化事件版本和未知格式版本；输出包含“完成/done”文字但无业务回执，让进程正常退出；提供可靠 reply ID 后再产生新一轮结果。
- **可观察结果：** 能力按安装版本与验证结果声明，observable/resumable/controllable 不凭品牌或另一个能力推定。未知解析器格式降级并保留原证据。普通文字和 exit code 只影响进程状态；可靠结果可产生未读事件，但 task.done 仍独立。外部 CLI 缺失不阻塞内部 Chela 聊天。
- **必要证据：** 版本与 ProbeCapabilities 结果、adapter parser 版本、官方事件夹具/原始输出、ExecutionObservation、Task/Delivery 变化及无回执场景。

### A30 · 回原终端与稳定结果定位

- **场景：** 同一任务有两次 CLI 执行，用户在另一聊天中收到第一现场的新结果提示。
- **操作 / 故障注入：** 点击带 terminal_session_id/result_ref/version 的路由，关闭/重开 tab；在原 PTY 存活、已结束和支持/不支持 resume 时分别操作。仅聚焦窗口，再明确查看可识别结果；验证中文输入、resize 与输出恢复。
- **可观察结果：** 定位正确原现场和结果，不误跳最新终端或当前聊天。关 tab 只释放视图，活 PTY 可重新连接；结束后打开归档，恢复能力可用才提供真实 resume，不新建空终端冒充。可靠 result 区域展示 ack 或明确用户操作才记 reply_seen，普通聚焦不足；查看不完成任务。启动使用 argv/验证过的 cwd，输入不被无意 shell 展开。
- **必要证据：** route、ExecutionLink 与外部 session ID、PTY/归档/resume 过程、reply_seen 证据、中文/resize 录像、合成危险字符参数的实际 argv。

## 九、旧能力与数据迁移：A31–A34

### A31 · 以真实工作区为准的功能清单

- **场景：** 用户本地可能已有新 Go 分支和未提交工作，远端基线仍是旧 Electron 版本。
- **操作 / 故障注入：** 在实施前只读识别当前分支、改动、入口、数据目录；将旧聊天、工具、记忆、planner、终端、角色、MCP/技能/扩展和生命周期能力逐项映射到新模块。对无法读取的新分支或历史描述明确标缺证据。
- **可观察结果：** 清单区分静态已核实、待核实和实际通过；每项有保留/迁移/替代及用户数据去向。不把远端 main 当用户当前状态，不覆盖未提交工作，不把会话里的“已完成”报告当测试。移除旧功能须有相应可用替代和验收证据。
- **必要证据：** 工作区只读报告、基线 commit/路径、功能映射、隔离迁移位置与回退点；无证据项保持待完成。

### A32 · 会话、记忆与快照迁移

- **场景：** 旧会话、memdir、向量库与工作快照中存在重复、来源缺失和未知 embedding 版本。
- **操作 / 故障注入：** 执行 detect/dry-run/backup/import/reconcile；导入中断后续跑，再完整重复一次。构造来源不明、相同文本但不同来源、旧快照覆盖不完整的记录。
- **可观察结果：** legacy ID 映射与校验清单完整，重复导入不复制数据，失败可恢复且切读前旧数据可用。来源/范围未知进入受限待分类，不虚构全局事实；向量不是正式记忆，未知 encoder 归档后重建。旧快照可查看，但未经新 Pi compaction/coverage 校验不能据此移除原文。
- **必要证据：** 导入前后计数/hash、legacy 映射、检查点/重复运行结果、未知数据处理清单与可读历史抽样。

### A33 · 旧任务、终端与交互模式迁移

- **场景：** 旧 planner、终端元数据、情绪模式及显式模式锁需要继承。
- **操作 / 故障注入：** 导入任务状态/期限、旧终端链接、focused/companion/quiet/encouraging/creative 与锁定设置；检验明确安静指令及旧 companion 自动转换边界。尝试用旧信号计数恢复新情绪分数。
- **可观察结果：** 旧任务不因进程退出变 done；终端历史能定位，缺失进程明确显示无法继续。旧模式映射到 InteractionMode，锁定保留；显式 cue 丢失及 confidence 0.6 被 `>0.6` 阻断的旧路径通过新逻辑消除。新 AffectState 从明确基线建立，不伪造历史心情；旧文件备份与一次导入标记保留。
- **必要证据：** 字段映射、导入前后任务/模式样本、两个旧缺口的回归场景、情绪初始化记录和终端历史导航证据。

### A34 · 旧工具与生命周期能力替换

- **场景：** 原有工具、Harness、终端、MCP、技能以及服务依赖管理迁入新分层。
- **操作 / 故障注入：** 用已盘点的常用任务走新路径；模拟缺失/循环依赖、部分服务启动失败和重复启停。双工具批次下检查旧 parallelManager 是否仍另起 executor；核对新旧压缩/MCP 注册是否并存。
- **可观察结果：** 有对应能力的任务能完成，缺能力给具体解释；服务按依赖顺序启动、反序解除，失败回滚已启动资源。旧事件解除订阅、PTY 清理和错误恢复能力被保留。每项只保留一个执行/压缩/连接所有者，不因迁移并行期双执行或双注册；旧实现移除依据 A31 清单。
- **必要证据：** 常用任务结果、服务依赖图/资源计数、启动失败与 teardown trace、工具实际执行次数和注册表差异。

## 十、桌宠与窗口：A35–A36

### A35 · 独立桌宠与展示仲裁

- **场景：** 主窗口隐藏，两个 Run 与一个明确提醒同时更新，用户在其他应用输入。
- **操作 / 故障注入：** 操作拖动、靠边、探头、点击、气泡与静音；切换全屏、多显示器和不同缩放；改变减少动态效果设置。让另一个 Run 试图同时抢占表现。
- **可观察结果：** 桌宠独立存活，以 presentation_id 仲裁单气泡/声音/动作；用户直接操作优先，后台合适合并。默认不抢焦点，点击才进入输入或原任务。本地动画无模型调用。透明、命中/穿透、置顶、遮挡、缩放和无障碍在每个声称支持的平台成立；渲染 adapter 替换不改变业务状态。
- **必要证据：** 目标平台矩阵与屏幕记录、焦点/输入结果、presentation 状态时间线、模型调用计数和未支持平台的明确说明。

### A36 · 隐藏、关闭、停止与退出

- **场景：** 前台聊天、后台关注、owned PTY 与用户独立进程同时存在。
- **操作 / 故障注入：** 依次主窗口 X、切页、关任务抽屉、隐藏桌宠、对话停止、托盘退出；在 UI 导航导致 bridge context 取消后重开；重连时丢失一次展示 ack，重启应用。
- **可观察结果：** X/导航只影响视图订阅，已提交 Run 由宿主生命周期持有并继续；隐藏桌宠保留后台和工作区未读。显式停止只取消目标 Run。退出有界保存并结束 owned 资源，将未收敛执行标中断，不杀独立外部进程。重开按 snapshot+cursor 恢复正式消息，流式片段不重复拼接；应用退出期间不宣称持续工作。
- **必要证据：** 操作与进程/Run 状态对照、context 所有权、重连消息计数与游标、关闭前后资源/进程树、退出及 catch-up 日志。

## 十一、模型与路由：A37–A38

### A37 · Magpie 目录、角色与离线降级

- **场景：** 模型目录正常、缓存过期、无缓存且离线三种状态；多个模型角色绑定同一 provider。
- **操作 / 故障注入：** 刷新目录/ETag，注入未知能力或价格，再断开 Magpie；按用户明确本地配置启动可用模型。分别请求本地任务、记忆浏览、确定性提醒和语义生成。
- **可观察结果：** 目录以真实 adapter 数据和缓存版本为依据，不维护另一套伪上游事实；unknown 不填猜测值，override 有来源。角色是用途绑定，不创造多个角色人格。目录离线时显示缓存日期；无可用路由时解释模型不可用，但本地功能继续。是否能推理取决于 endpoint，不只看目录缓存存在。
- **必要证据：** 原始目录夹具、CatalogSnapshot/role binding/override、ResolveRoute 输出、离线功能记录与请求实际 endpoint；凭据仅留引用。

### A38 · 模型切换、能力与 encoder 版本

- **场景：** 当前 Run 使用工具或图像，用户切到较小窗口/不支持该能力的模型；embedding 也准备升级。
- **操作 / 故障注入：** 工具执行中切模型，模拟原模型不可用并开启/关闭 fallback；切换 embedding encoder，重建期间查询旧/新索引。
- **可观察结果：** 模型配置在安全边界生效，已发工具不重放；实际模型与 requested 模型可追踪。不兼容 fallback 被阻止或要求改变任务，不能静默丢图像/工具。上下文按新预算重装。embedding 数据按 encoder/version 分区或转换，不混算不同空间相似度；重建失败保留正式记忆和有效降级路径。
- **必要证据：** 各步配置指纹、requested/actual、能力检查、ContextManifest、工具计数、索引版本与检索结果。

## 十二、扩展、工具与信任：A39–A41

### A39 · Pi 扩展兼容分级与 UI 桥

- **场景：** 安装 A 资源、B 生命周期/custom entry、C 简单交互、D TUI 自定义、E 私有 API 扩展各一项。
- **操作 / 故障注入：** 在固定 SDK 上启用并调用；C 请求在用户切换会话、取消 Run、重启 worker 时返回；D 请求真实 TUI 能力；给一个直接用 Node I/O 的普通第三方扩展查看信任声明。
- **可观察结果：** A–E 兼容等级与 managed/trusted-native 分别声明，支持范围真实。简单 UI 带 session/run/request ID 和超时，不把回答发给另一会话；WebView 使用 rpc 语义，不伪装 tui。D/E 未适配明确不支持。直接 Node I/O 扩展不被宣称已受 Go 网关或 OS 沙箱约束，未信任输出仍只作为资料。
- **必要证据：** 扩展 manifest/hash/兼容结果、UI request-reply 因果、取消/超时记录、能力面板和实际 tool 路由。

### A40 · 能力生命周期与单一连接所有者

- **场景：** 多个模块/插件具有依赖、工具命名空间和 MCP 连接；运行中准备升级。
- **操作 / 故障注入：** 注入依赖环、同名注册、启动中途失败；反复启停和 reload。让 Go 与 Pi 扩展同时要求拥有同一 MCP 连接；发现一个延迟加载工具并检查完整 schema；活动 Run 中提交升级。
- **可观察结果：** 启动前校验，部分失败回滚资源；dispose 消除定时器/监听/连接，不随 reload 增殖。同连接只有一个 owner，同名冲突明确拒绝。工具发现能取得名称和 schema，实际调用版本固定。代码/工具表升级在 idle 安全边界生效，必要时重建 worker，不能静默改变活动调用。
- **必要证据：** CapabilityRegistry、连接/注册/监听计数、启动/teardown trace、工具 schema 与版本指纹、升级前后 Run 配置。

### A41 · 资料、权限与不可信页面

- **场景：** 网页、项目文件、记忆和工具结果含“忽略规则/发送密钥”的内容，另有生成 HTML 预览。
- **操作 / 故障注入：** 让模型读取合成诱导资料，尝试扩大 scope 或调用未经授权工具；在不可信 WebView/origin 中调用 Go bridge；伪造本地 IPC worker 身份、epoch 或请求参数。验证已有明确授权的正常可逆操作。
- **可观察结果：** 资料不能升级成用户命令；Go 按当前 policy/RunScope 和最终参数执行，未经授权动作受阻。可信 UI 的隐藏按钮不是唯一防线；不可信页面无特权桥，IPC 身份/参数校验，管理端点不默认暴露到局域网。普通已授权操作不被额外审批循环拖住；trusted-native/外部 CLI 的独立权限边界如实说明。
- **必要证据：** 合成输入、PolicyDecision/拒绝码、实际副作用为零的目标证据、WebView/IPC 记录、正常已授权操作通过轨迹；不得使用真实密钥做夹具。

## 十三、可靠性、备份与发布：A42–A46

### A42 · 各崩溃阶段与新恢复 Run

- **场景：** 工具执行跨越多个持久化阶段，worker 或宿主可能在任一步退出。
- **操作 / 故障注入：** 分别在 planned、executing 前、外部副作用已发生但结果未提交、result 已提交但 Pi 未收到、最终 checkpoint 未 ack 时终止进程；加入已提交 assistant 多工具调用但结果未齐的夹具；恢复后重复投递相同 invocation 和旧 worker 事件。
- **可观察结果：** 原 Run 终态不可复活，继续工作使用新恢复 Run 并保留关联。已提交结果可复用；可证明未执行才允许重试；结果未知进入 outcome_unknown/reconciliation，不能盲目重放无幂等副作用。恢复输入区分已证实/未证实/不可重放。未配对 tool calls 不能直接发送 provider：须经验证过的 adapter 补齐诚实结果，或从最后完整安全边界建立恢复上下文并交接 Go 工具日志；原始记录保留，unknown 不伪造成功。新 run_id 本身不解决消息协议恢复，新 attempt 也不伪装原 JavaScript 栈或 CLI 内存；迟到已知结果仍归原调用日志。
- **必要证据：** 每个故障切点、实际目标状态、invocation/Run/attempt 日志、新旧关联与重复执行计数、reconciliation 决定、恢复后实际模型请求的工具配对；必须观察真实夹具副作用。

### A43 · 存储故障、事件恢复与诊断边界

- **场景：** 磁盘满、SQLite 不可写、blob 半写、UI 慢消费和事件 cursor 过期。
- **操作 / 故障注入：** 在 command/outbox 与 blob 发布前后注入失败；令读者持有短快照、重复 outbox 分发、断开 UI 后继续写入，再超出保留窗重连。另让诊断日志写入失败。
- **可观察结果：** 失败事务不发布成功或启动尚无日志保障的新副作用；只读功能准确降级。blob 完整写入才可发布引用，孤儿可 GC，在途引用不误删。快照与 cursor 同读事务，订阅补齐无洞，至少一次事件经消费去重；过期 cursor 明确要求重取快照，慢 UI 不无限缓存。诊断失败不撤销已提交业务；日志不自动泄露内容/密钥。
- **必要证据：** DB/outbox/blob 一致性快照、故障返回与事件序列、消费 cursor/去重记录、GC 引用、内存观测及脱敏诊断样本。

### A44 · 一致备份与受控恢复

- **场景：** WAL 模式下持续有写入，备份包含附件、插件清单、未完成工具和删除登记。
- **操作 / 故障注入：** 活跃期间使用支持的一致性备份方法；校验后恢复到空目录；分别损坏 blob/checksum、换成不支持 schema/Pi 格式，并套用较新遗忘登记后再开放读取。
- **可观察结果：** 备份包括一致 DB 与附件 manifest，不靠只复制活跃 .db。校验失败拒绝切读，原数据保持可用；恢复版本有解释且不丢原始字段。删除登记先于检索恢复，恢复不自动执行历史 pending 写操作或旧审批。能力可浏览和未完成项可解释，不夸称精确续跑。
- **必要证据：** 备份 manifest/hash、SQLite 备份方式与一致性检查、恢复步骤/拒绝记录、附件对账、删除后查询与副作用执行计数。

### A45 · 可复现安装与无副作用 bindings

- **场景：** 发布包在每个声称支持的目标平台安装，构建过程执行 MyGo bindings 生成。
- **操作 / 故障注入：** 从锁定依赖重建产物；在无全局 Node/Pi、无在线 npm 的干净环境安装；分别缺失平台 WebView 依赖。生成 bindings 时监控用户数据目录、进程和定时器；查询真正链接的 SQLite 版本/source ID。
- **可观察结果：** 包含 Go、Web、私有 Node、worker 和必要资源，缺平台依赖给准确路径。lockfile/Go 校验与构建依赖可追溯，不因源码 `^` 在发包时漂移。bindings 不启动服务、worker、数据库迁移或后台定时器。SQLite 内核与 [07 发布要求](../docs/architecture/07-reliability-release.md) 的修复门禁一致，不能只拿驱动包版本证明。
- **必要证据：** 构建/安装 manifest、锁文件与工具链、实际进程/文件访问、离线启动结果、SQLite version/source ID、目标平台安装与核心交互记录。

### A46 · 升级、回退与发布证据

- **场景：** 应用/schema/Pi 或 adapter 升级，安装中断，用户需要回到可用版本。
- **操作 / 故障注入：** 使用副本迁移旧数据；在备份、迁移、包替换各阶段中断；让旧程序打开新 schema；更新一次影响 SDK 的依赖并执行受影响门禁。记录目标机器上的启动、前后台并发、内存与关键延迟。
- **可观察结果：** 升级前有可读备份/校验与真实 dry-run 报告，迁移有检查点，未完成时不切读。旧程序拒绝写新 schema；回退安装配合匹配数据备份，不假装任意 down migration。安装失败保留旧版本与诊断，owned 执行有界停止。发布报告逐项列实际通过/失败/未执行平台与 A ID，性能只针对所测配置，不伪称通用指标；未覆盖的硬门禁不能以文档完成替代。
- **必要证据：** 升级/回退演练与备份哈希、schema/app/Pi 格式关系、受影响验收结果、实际硬件/版本和测量数据、诊断导出脱敏样本及未决风险列表。

## 实施报告最小模板

每个阶段只需要一份工程报告，关联实际执行的 ID；无需为最终用户增加页面或表单。

```text
build / commit:
environment / versions / fixed configuration:
acceptance_id:
status: not_run | passed | failed | blocked
executed_at:
scenario / injected_failure:
observed_result:
evidence_paths:
remaining_issue / affected_scope:
```

跨阶段复用证据时保留对应构建、依赖和适用范围。架构边界变化需要重新验证相关门禁；纯文案等低影响修改不因此扩展成全量测试。
